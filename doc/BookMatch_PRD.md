# BookMatch PRD

## 1. Executive Summary

### 1.1 제품 개요

책 선택에 피로를 느끼는 독자가 90초 성향 테스트와 시간 기반 독서 회고를 통해, 평점 입력 없이도 즉시 정확한 맞춤 추천을 받는 서비스입니다.

### 1.2 핵심 가치 제안 (Key Value Proposition)

기존 도서 추천 서비스가 가진 구조적 한계(진입장벽, 선택 피로, 인사이트 부재)를 해결하기 위해 다음과 같은 차별화된 가치를 제공합니다.

| 핵심 가치 | 기존 서비스 (Pain Point) | BookMatch Solution |
|-----------|--------------------------|-------------------|
| 즉시 추천 (콜드스타트 해결) | 10~20개 평점 입력 필요 (5~10분 소요) 초기 추천 정확도 낮음 (40~50%) | 90초 MBTI 테스트로 성향 파악 신규 가입 즉시 60% 정확도 추천 제공 |
| 선택 피로 제거 (Choice Overload) | 20~50권 나열식 추천 명확한 근거 부재 ("확률 92%") | 딱 3권만 제안 성향 일치 + 독자 만족 + 의외성 기반의 명확한 이유 제시 |
| 독서 회고 (Insight) | 단순 통계 나열 (읽은 책 N권) 패턴 분석 및 피드백 부재 | 월말/연말 리포트 자동 생성 독서 패턴 분석 및 다음 단계 책 제안 (Spotify Wrapped 벤치마크) |

### 1.3 타겟 사용자

**Primary: 책 고르기 어려운 독서 초심자 (월 1~2권)**
- Pain Point: "읽고 싶은데 뭘 읽어야 할지 모르겠어요. 가입하자마자 평점 남기기도 귀찮아요."
- Needs: 복잡한 절차 없이 내 취향에 맞는 책을 바로 추천받고 싶음.

**Secondary: 독서 기록 관리에 관심 있는 중급 독자 (월 3~5권)**
- Pain Point: "읽은 책을 기록하고 싶은데, 단순 나열만 되면 재미없고 의미를 모르겠어요."
- Needs: 나의 독서 패턴을 시각적으로 확인하고, 변화하는 취향에 맞는 책을 제안받고 싶음.

### 1.4 주요 성과 목표 (3개월)

기술적 정확도와 사용자 참여를 동시에 달성하는 것을 목표로 합니다.

| 구분 | 핵심 지표 (KPI) | 목표치 | 설정 근거 |
|------|----------------|--------|-----------|
| 추천 품질 | 신규 유저 추천 수락률 | 60% | 콜드스타트 해결 시 CTR 상승 예측 연구 기반¹ |
| | 성숙 유저(6권+) 수락률 | 80% | 하이브리드 필터링 적용 시 정확도 향상 |
| 사용자 참여 | 온보딩(테스트) 완료율 | 85% | 테스트형 온보딩의 높은 완료율 (일반 대비 1.5배)² |
| | 월말 리포트 열람률 | 80% | Spotify Wrapped 24시간 참여율 28% 및 높은 관여도 반영 |

> ¹ Expert Systems with Applications, 2024 / ² KPI Depot, "Onboarding completion rate guidelines"

## 2. 문제 정의 (Problem Statement)

### 2.1 시장 현황 및 구조적 한계

기존 도서 플랫폼(왓챠피디아, 밀리의서재 등)은 방대한 데이터를 보유하고 있으나, 신규 사용자 경험과 지속적인 동기 부여 측면에서 세 가지 명확한 한계를 보입니다.

#### (1) 콜드스타트 문제 (Cold Start Problem)

대부분의 추천 알고리즘은 협업 필터링(Collaborative Filtering)에 의존합니다. 이는 충분한 사용자 데이터가 쌓이기 전까지 추천 품질이 현저히 떨어지는 문제를 야기합니다.

> "사용자 히스토리가 풍부할수록 성능이 개선되고, 콜드스타트 상황에서 정확도가 떨어진다."
> — Cambridge, Knowledge Engineering Review, 2023

- **현상**: 신규 가입자에게 10~20개의 평점 입력을 강요함.
- **임팩트**: 입력 피로도로 인한 온보딩 이탈 발생, 초기 추천 정확도 40~50% 수준에 머무름.

#### (2) 선택 과부하 (Choice Overload)

사용자에게 너무 많은 선택지를 제공하면 오히려 선택을 포기하거나 만족도가 떨어지는 심리학적 현상이 발생합니다.

- **현상**: "오늘의 추천" 탭에서 20~50권의 도서를 단순 나열.
- **임팩트**: 하위 목록의 클릭률(CTR)은 5% 미만으로 무의미하며, 사용자는 결국 베스트셀러 1위를 선택하거나 이탈함.

#### (3) 의미 없는 독서 기록 (Lack of Insight)

기록 기능이 존재하지만, 단순 데이터베이스 역할에 그쳐 사용자에게 가치를 제공하지 못합니다.

- **현상**: 읽은 책 목록과 평점을 시간순으로 나열하는 데 그침.
- **임팩트**: Spotify Wrapped와 같이 데이터를 '인사이트'로 전환하여 참여를 이끌어내는 요소(Viral loop)가 부재함.

### 2.2 핵심 문제 요약

| 문제 영역 | 현재 상태 (ASIS) | 이상적 상태 (TOBE) | 비즈니스 기회 |
|-----------|------------------|-------------------|---------------|
| 진입장벽 | 평점 10개 입력 강요 (이탈률 높음) | 90초 테스트로 즉시 시작 | CPA(유저 획득 비용) 절감 초기 리텐션 확보 |
| 추천 경험 | 수십 권 나열 (선택 포기) | 3권 큐레이션 | 추천 도서 구매/완독 전환율 상승 |
| 리텐션 | 단순 기록 저장소 (동기 부여 없음) | 주기적 회고 리포트 | 장기 리텐션 및 자발적 바이럴(SNS 공유) |

## 3. 솔루션 및 차별화 전략

### 3.1 핵심 솔루션 프레임워크

BookMatch는 사용자의 생애 주기(Life Cycle)에 맞춰 진화하는 3단계 솔루션을 제공합니다.

#### Phase 1: 즉시 추천 (콜드스타트 해결)

- **What**: 독서 MBTI 성향 테스트 (8문항)
- **로직**: 4가지 축(몰입도, 이성/감성, 현실/상상, 속도)을 기반으로 16가지 독서 성향(예: DELF형)으로 분류.
- **매칭**: 사용자 성향 키워드와 도서 리뷰에서 추출한 TF-IDF 키워드 간의 코사인 유사도 분석을 통해 콘텐츠 기반 추천(Content-based Filtering)을 즉시 수행.

#### Phase 2: 지속 학습 (정확도 고도화)

- **What**: 하이브리드 추천 시스템
- 초기(1~5권 평가): 콘텐츠 기반(70%) + 사용자 패턴(30%) 가중치 적용.
- 성숙(6권 이상): 협업 필터링(User-based Collaborative Filtering) 비중을 50%까지 확대하여, 나와 비슷한 취향을 가진 타 사용자의 데이터를 활용해 추천 범위를 확장.

#### Phase 3: 회고와 재시작 (Lock-in)

- **What**: 월말/연말 리포트 & 시의적절한 제안
- **분석**: 단순 통계가 아닌 '취향 변화', '핵심 키워드', '감정 흐름'을 시각화.
- **액션**: 회고 데이터를 바탕으로 다음 달에 읽어야 할 책(안전한 선택 vs 새로운 도전)을 자동으로 제안하여 독서의 연속성을 보장.

### 3.2 6가지 핵심 차별화 포인트

| 구분 | 구현 방식 | 기대 효과 및 경쟁 우위 |
|------|----------|----------------------|
| 1. 독서 MBTI | 8문항 2지선다 테스트 (90초 소요) 16가지 성향 유형 분류 및 키워드 매칭 | 신규 유저 추천 정확도 60% 확보 (경쟁사 대비 진입 시간 80% 단축) |
| 2. 3권 집중 추천 | 유사도 상위 10개 중 다양성 필터 적용 최종 3권 선정 (성향 일치 / 독자만족 / 의외성) | 선택 피로 제거 및 전환율 70% 목표 (무의미한 나열식 추천 지양) |
| 3. 설명 가능한 추천 (XAI) | 추천 이유 1줄 명시 "당신이 좋아한 'OOO'과 분위기가 87% 유사해요" | 사용자 신뢰도 상승 (단순 "추천 확률 92%" 대비 설득력 강화) |
| 4. 네거티브 학습 | "별로예요" 평가의 공통 속성(분량, 번역투 등)을 분석하여 향후 추천에서 자동 필터링 | 불만족 경험 최소화 (기존 서비스에 부재한 '싫어하는 이유' 분석) |
| 5. 시간 기반 회고 | 매월 말일/연말 자동 리포트 생성 SNS 공유 최적화 이미지 제공 | 자발적 바이럴 및 재방문 유도 (도서 앱 최초의 Spotify Wrapped 모델 도입) |
| 6. 단계별 알고리즘 | 데이터 축적량에 따라 알고리즘 가중치 자동 조절 (콘텐츠 기반 → 하이브리드) | 전 구간 고품질 추천 유지 (경쟁사의 신규 유저 품질 저하 문제 해결) |

### 3.3 경쟁 우위 및 포지셔닝

BookMatch는 "콜드스타트부터 장기 사용자까지, 끊김 없는 맞춤 경험을 제공하는 유일한 서비스"로 포지셔닝합니다.

| 항목 | 왓챠피디아 (Big Data) | 밀리의서재 (Subscription) | BookMatch (Personalization) |
|------|----------------------|--------------------------|----------------------------|
| 초기 진입 | 높은 장벽 (평점 10+개) | 낮은 장벽 (구독 결제) | 장벽 없음 (90초 테스트) |
| 추천 방식 | 협업 필터링 중심 (데이터 의존도 높음) | 카테고리/인기순 나열 (개인화 부족) | 하이브리드 & 맥락 기반 (신규/기존 모두 최적화) |
| 사용자 경험 | 탐색 및 평가 위주 | 다독 및 열람 위주 | 발견(Discovery) 및 회고(Review) |
| 기록의 가치 | 개인 DB 저장용 | 독서 이력 확인용 | 인사이트 및 소셜 공유용 |

## 4. 제품 기능 명세

### 4.1 MVP 기능 (Phase 1)

MVP의 목적은 다음 한 줄로 정리된다.

> "신규 사용자가 최소한의 입력으로 개인화 추천을 받고, 읽음 → 평가 → 재추천의 학습 루프를 자연스럽게 경험하게 한다."

이에 따라 MVP 기능은 다음 4가지로 한정한다.

1. 독서 MBTI 기능
2. 도서 추천 기능
3. 독서 위시리스트 기능
4. 도서 평가 기능

#### 4.1.1 독서 MBTI 테스트

**기능 개요**
- **기능 설명**: 사용자의 독서 성향을 4가지 축(몰입도, 감성/이성, 현실/상상, 전개 속도)으로 분류하여 16가지 독서 유형 중 하나를 도출하는 테스트
- **도입 목적**: 신규 사용자 콜드스타트 문제를 해결하고, 평점 입력 없이도 즉시 개인화 추천을 제공하기 위함

**사용자 진입 조건**
- **진입 시점**: 회원가입 직후 최초 1회
- **진입 경로**: 랜딩 페이지 → 회원가입 완료 → 독서 MBTI 테스트 자동 진입

**입력 / 출력**
- **입력값**: 8문항 2지선다 응답(A/B)
- **출력값**:
  - 독서 유형 코드(예: DELF)
  - 유형 한 줄 설명
  - 유형 상세 설명
  - 선호 장르 / 대표 키워드 리스트
  - 추천 도서 목록

**주요 동작 규칙**
- 규칙 1: 각 축은 2문항으로 구성되며, 선택지에 따라 점수를 누적한다.
- 규칙 2: 각 축 점수가 동점일 경우 사전 정의된 우선 규칙을 적용한다.
- 규칙 3: 테스트 결과는 사용자 독서 성향의 기준값으로 저장되며, 이후 추천 로직의 기본 입력값으로 사용된다.

**예외 및 제한 사항**
- 케이스 1: 테스트를 중도 이탈한 경우 → 로그인 시 테스트 재진입 유도
- 케이스 2: 이미 테스트를 완료한 사용자는 기본적으로 재응시 불가
- 케이스 3: 비로그인 사용자는 테스트를 수행할 수 없음

#### 4.1.2 도서 추천 기능

**기능 개요**
- **기능 설명**: 독서 MBTI와 사용자 행동 데이터를 기반으로 개인화된 도서를 추천하는 기능
- **도입 목적**: 사용자의 선택 피로를 최소화하면서 "나에게 맞는 책"을 빠르게 제안하기 위함

**사용자 진입 조건**
- **진입 시점**: 로그인 완료 후 메인 화면 진입 시
- **진입 경로**: 로그인 → 메인 추천 화면

**입력 / 출력**
- **입력값**:
  - 독서 MBTI 유형
  - 사용자 도서 평가 기록 데이터(있을 경우)
- **출력값**:
  - 추천 도서 3권
  - 각 도서별 추천 이유 및 라벨 정보

**주요 동작 규칙**
- 규칙 1: 추천 도서는 항상 3권만 제공하여 선택 피로를 최소화한다.
- 규칙 2: 서평 기록이 없는 경우, 콘텐츠 기반 추천을 적용한다.
- 규칙 3: 서평 기록이 누적될수록 사용자 선호 패턴을 반영하여 추천 결과를 조정한다.
- 규칙 4: 모든 추천 결과에는 반드시 "추천 이유"를 함께 제공한다.

**예외 및 제한 사항**
- 케이스 1: 사용자 데이터가 부족한 경우에도 추천 결과는 항상 제공되어야 한다.
- 케이스 2: 추천 후보군이 부족할 경우, 다양성 필터 조건을 완화하여 재추천한다.

#### 4.1.3 도서 위시리스트 기능

**기능 개요**
- **기능 설명**: 추천된 도서를 임시로 저장해두고, 이후 독서 완료 처리 또는 제거할 수 있는 간단한 보관 기능
- **도입 목적**: 추천 결과를 즉시 소비하지 못한 사용자의 이탈을 방지하고, "나중에 읽기"라는 명확한 행동 경로를 제공하기 위함

**사용자 진입 조건**
- **진입 시점**: 추천 도서가 노출된 시점
- **진입 경로**: 메인 추천 화면 → 추천 도서 카드 → 위시리스트 추가 버튼
- ※ 검색, 외부 도서 탐색을 통한 진입 경로는 MVP에서 제공하지 않음

**입력 / 출력**
- **입력값**:
  - 위시리스트 추가 / 제거 버튼 클릭
  - 독서 완료 처리 버튼 클릭
- **출력값**:
  - 위시리스트 저장 상태(추가/제거)
  - 위시리스트 목록
  - 독서 완료 처리 결과(서평 기록 단계로 전환)

**주요 동작 규칙**
- 규칙 1: 위시리스트에는 추천된 도서만 추가할 수 있다.
- 규칙 2: 위시리스트에서 가능한 액션은 다음 두 가지로 제한한다.
  - 위시리스트에서 제거
  - 독서 완료 처리
- 규칙 3: 독서 완료 처리 시, 해당 도서는 위시리스트에서 제거되며 서평 기록 플로우로 자연스럽게 연결된다.

**예외 및 제한 사항**
- 케이스 1: 동일 도서는 위시리스트에 중복 추가할 수 없다.
- 케이스 2: 위시리스트에 추가된 상태라도 추천 로직에는 직접적인 가중치를 주지 않는다 (MVP에서는 단순 보관 기능으로만 활용)

#### 4.1.4 도서 평가 기록 기능

**기능 개요**
- **기능 설명**: 사용자가 책을 읽은 후 좋아요/별로 선택만으로 독서 완료를 기록하는 기능
- **도입 목적**: 평가 부담을 최소화하여 추천 알고리즘 학습 데이터를 빠르게 확보하기 위함

**사용자 진입 조건**
- **진입 시점**: 독서 완료 시점
- **진입 경로**:
  - 추천 도서 상세 → "읽었어요" 버튼
  - 위시리스트 → "독서 완료" 버튼

**입력 / 출력**
- **입력값**: 좋아요 👍 / 별로 👎 (필수)
- **출력값**:
  - 독서 완료 상태 저장
  - 다음 추천에 반영되었다는 안내 메시지

**주요 동작 규칙**
- 규칙 1: 서평 기록은 좋아요/별로 선택만으로 완료된다.
- 규칙 2: 서평 기록 완료 시 해당 도서는 "읽은 책"으로 처리된다.
- 규칙 3: 저장된 평가는 추천 알고리즘에 즉시 반영된다.

**예외 및 제한 사항**
- 케이스 1: 좋아요/별로를 선택하지 않으면 서평 기록을 완료할 수 없다.
- 케이스 2: MVP 단계에서는 평점, 텍스트 후기, 태그 입력을 제공하지 않는다.
- 케이스 3: 동일 도서에 대해 중복 서평 기록은 불가능하며 재평가 시 기존 값을 덮어쓴다.

### 4.2 핵심 차별화 기능 (Phase 2)

Phase 2의 목적은 단순한 기능 추가가 아니다.

> 독서 추천 서비스를 '기록 → 해석 → 다음 행동'이 이어지는 **독서 회고 서비스**로 확장하는 것

이를 위해 월 단위, 연 단위로 사용자의 독서 데이터를 의미 있는 스토리로 재구성한다.

#### 4.2.1 월말 정산

**기능 개요**
- **기능 설명**: 한 달간의 독서 활동 데이터를 자동으로 분석하여 통계, 해석, 다음 달 추천을 포함한 월말 독서 리포트를 제공하는 기능
- **도입 목적**: 독서 기록에 '의미'를 부여하여 재방문을 유도하고, 다음 달 추천의 설득력을 강화하기 위함

**사용자 진입 조건**
- **진입 시점**: 매월 말일 리포트 생성 이후
- **진입 경로**:
  - 푸시 알림 → 월말 리포트 화면
  - 마이페이지 → 월별 리포트 아카이브

**입력 / 출력**
- **입력값**: 해당 월에 생성된 서평 기록 데이터(👍/👎 기준)
- **출력값**:
  - 월말 독서 리포트
  - 월말 리포트 기반 다음 달 추천 도서 3권

**주요 동작 규칙**
- 규칙 1: 해당 월에 서평 기록이 1권 이상 존재할 경우에만 리포트를 생성한다.
- 규칙 2: 월말 리포트는 다음 요소를 반드시 포함한다.
  - 기본 통계(읽은 책 수, 평균 평가, 총 페이지 수, Top 장르)
  - 핵심 키워드 Top 3
  - 감정 변화 추이
  - 장르 분포 시각화
  - AI 코멘트(템플릿 + 데이터 결합)
- 규칙 3: 월말 리포트 생성 시, 해당 리포트를 기반으로 다음 달 추천 도서 3권을 함께 생성한다.
- 규칙 4: 월말 추천은 일반 추천과 구분되어 "이번 달을 돌아본 추천"임을 명시한다.

**예외 및 제한 사항**
- 케이스 1: 해당 월에 서평 기록이 없는 경우, 리포트를 생성하지 않는다.
- 케이스 2: 이미 생성된 월말 리포트는 동일 월 내 재생성하지 않는다.
- 케이스 3: 월말 리포트 미열람 시에도 서비스 이용에는 제한이 없다.

#### 4.2.2 연말 결산 기능

**기능 개요**
- **기능 설명**: 1년간의 독서 데이터를 종합 분석하여 연간 독서 결산 리포트를 제공하는 기능
- **도입 목적**: "올해의 나"를 요약한 공유 가능한 결과물을 제공하고, 새해 독서 목표 및 추천으로 다음 사용 사이클을 시작하게 하기 위함

**사용자 진입 조건**
- **진입 시점**: 12월 31일 연말 결산 생성 이후
- **진입 경로**:
  - 푸시 알림 → 연말 결산 화면
  - 마이페이지 → 연말 결산 아카이브

**입력 / 출력**
- **입력값**: 해당 연도 전체 서평 기록 데이터
- **출력값**:
  - 연말 결산 리포트
  - 공유용 이미지
  - 새해 추천 도서 3권
  - 독서 목표 설정 화면

**주요 동작 규칙**
- 규칙 1: 연간 서평 기록이 5권 이상일 경우에만 연말 결산을 생성한다.
- 규칙 2: 연말 결산은 다음 요소를 반드시 포함한다.
  - 연간 통계(총 권수, 평균 평가, 총 페이지 수, 최고의 달)
  - 올해의 키워드(워드클라우드)
  - 독서 스타일 변화(상반기 vs 하반기)
  - 최고의 책 Top 3
  - 독서 유형 변화(작년 대비)
  - 동일 유형 사용자 대비 비교 데이터
  - 공유 가능한 시각적 결과물
- 규칙 3: 연말 결산 확인 이후, 새해 추천과 독서 목표 설정으로 자연스럽게 연결한다.

**예외 및 제한 사항**
- 케이스 1: 조건을 충족하지 못한 경우 "아직 결산할 데이터가 부족해요" 안내를 노출한다.
- 케이스 2: 이미 생성된 연말 결산은 해당 연도 내 수정할 수 없다.

### 4.3 향후 확장 기능 (Phase 3 이후)

#### 1. 콘텐츠 및 데이터 확장
- 도서 데이터 1,000권 이상 확장
- 장르 세분화(시, 고전, 과학, 육아, 취미 등)
- 외부 도서 API 연동을 통한 빠른 도서 등록

#### 2. 추천 알고리즘 고도화
- 감성 분석 점수 반영(기분/분위기 기반 추천)
- 상황 기반 추천(출퇴근, 여행, 번아웃 등)
- 문장 임베딩 기반 유사도 추천

#### 3. 사용자 경험 확장
- 대량 등록(CSV 업로드)
- 리포트 템플릿 선택 기능
- 소셜 기능(유형별 인기 책, 비교, 리포트 반응)

#### 4. 운영 및 성장 기능
- 시즌별 큐레이션 이벤트
- 개인화 리마인드 알림(리포트, 목표, 위시리스트)

## 5. 사용자 경험 설계

### 5.1 핵심 사용자 플로우

본 서비스의 UX 설계 목표는 다음과 같다.

> 최소한의 입력으로 개인화 가치를 빠르게 체감하게 하고,
> 추천 → 기록 → 재추천의 학습 루프를 자연스럽게 반복하게 한다.

이를 위해 사용자 여정을 신규 사용자 / 일반 재방문 / 회고 시점 사용자로 구분한다.

#### 5.1.1 신규 가입자 여정 (콜드스타트 → 즉시 가치)

**목표**
- 가입 직후 "이 서비스는 나를 이해한다"는 인식 형성
- 입력 부담 없이 개인화 추천 경험 제공

**플로우**
```
랜딩 페이지 → 회원가입 → 독서 MBTI 테스트 → 독서 유형 결과 → 추천 도서 3권 노출
                                                                    ↓
                                                        관심 있음 → 위시리스트 추가
                                                        이미 읽음 → 읽었어요 버튼 → 👍/👎 평가 모달
                                                                                      ↓
                                                                    도서 평가 기록 리스트에 추가 → 추천 로직 학습 → (반복)
```

**UX 설계 포인트**
- MBTI 테스트는 자동 진입하여 다음 행동 고민을 제거
- 테스트 결과 화면에서 유형 설명 + "이런 이유로 이 책들을 추천했어요"를 명시
- 추천은 항상 3권만 노출하여 선택 피로 최소화

#### 5.1.2 재방문 사용자 여정 (학습 루프)

**목표**
- 반복 사용 시 추천 정확도가 점점 높아진다는 체감 제공
- 평가를 '리뷰 작성'이 아닌 '가벼운 반응'으로 인식하게 함

**플로우**
```
로그인 → 메인 추천 화면 → 추천 도서 3권
                              ↓
                관심있음 → 위시리스트 추가 → 위시리스트 화면 → 독서 완료 → 👍/👎 평가
                이미읽음 → 읽었어요 버튼 → 👍/👎 평가
                                              ↓
                              도서 평가 기록 리스트에 추가 → 추천 로직 학습 → 메인 추천 화면
```

**UX 설계 포인트**
- 평가 입력은 좋아요/별로 1회 클릭으로 완료
- 평가 완료 후 "다음 추천에 반영했어요" 메시지 노출
- 위시리스트는 "나중에 읽기"를 위한 임시 저장소로만 사용 (복잡한 관리 기능은 제공하지 않음)

#### 5.1.3 월말/연말 시즌 여정 (회고 → 다음 사이클)

**목표**
- 한 달, 1년 독서 경험을 성과물로 제공
- 공유 → 유입 → 다음 달/해 사용으로 연결

**월말 결산 플로우**
```
월말 도래 → 해당 월 평가 ≥ 1권?
              ↓ Yes                    ↓ No
      월말 리포트 생성 → 푸시 알림 발송   리포트 미생성
              ↓
      월말 리포트 화면 → 이번 달 요약/해석 → 다음 달 추천 3권
                                                ↓
                                관심있음 → 위시리스트 추가
                                이미읽음 → 읽었어요 버튼 → 👍/👎 평가 모달
                                                            ↓
                                          도서 평가 기록 리스트에 추가 → 추천 로직 학습 → 메인 추천 화면
```

**연말 결산 플로우**
```
12월 31일 → 연간 평가 ≥ 5권?
              ↓ Yes                    ↓ No
      연말 결산 생성 → 푸시 알림 발송    결산 미생성
              ↓
      연말 결산 화면 → 연간 요약/변화 분석 → 공유 이미지 생성
                                          → 새해 추천 3권
                                               ↓
                               관심있음 → 위시리스트 추가
                               이미읽음 → 읽었어요 버튼 → 👍/👎 평가 모달
                                                           ↓
                                         도서 평가 기록 리스트에 추가 → 추천 로직 학습 → 메인 추천 화면
```

**UX 설계 포인트**
- 연말 결산은 공유를 전제로 디자인
- "작년의 나" → "올해의 목표"로 자연스럽게 연결
- 목표 설정은 선택 사항으로 부담 없이 유도

### 5.2 주요 화면 구성

#### 5.2.1 MVP 화면
- 랜딩 페이지
- 회원가입 / 로그인
- 독서 MBTI 테스트 화면
- 독서 MBTI 결과 화면
- 메인 추천 화면 (3권)
- 위시리스트 화면
- 도서 평가(👍/👎) 모달
- 도서 평가 기록 리스트 화면

#### 5.2.2 개선 후 화면 (Phase 2)
- 월말 독서 리포트 화면
- 연말 독서 결산 화면
- 공유 이미지 미리보기 화면

### 5.3 UX 설계 원칙

#### ① 입력 최소화 원칙
- 모든 핵심 행동은 클릭 1~2회 이내 완료
- MVP 단계에서는 텍스트 입력 최소화

#### ② 설명 가능한 개인화
- 모든 추천에는 반드시 추천 이유를 제공
- "왜 이 책인가요?"에 대한 답을 UX로 노출

#### ③ 선택 피로 제어
- 추천 도서는 항상 3권만 제공
- 무한 스크롤, 대량 리스트 제공 지양

#### ④ 기록의 의미 강조
- 단순 통계보다 해석 문장을 우선 노출
- 월말/연말 리포트는 "요약 → 맥락 → 다음 행동" 구조

#### ⑤ 다음 행동 유도형 설계
- 모든 주요 화면 하단에는 다음 행동 CTA 배치
  - 추천 → 위시리스트 / 읽기
  - 리포트 → 다음 달 추천
  - 연말 결산 → 새해 목표 설정

#### 6.2.1 알고리즘 전체 구조


#### 6.2.3 다양성 필터 (Diversity Filter)

추천의 질을 높이기 위해 상위 10개 후보 중 최종 3권을 선정할 때 다양성을 고려합니다.

```python
def select_final_3(candidates):
    """
    3가지 기준으로 다양성 확보:
    1. 성향 일치: 가장 높은 유사도 점수
    2. 독자 만족: 평균 평점이 높은 책
    3. 의외성: 유사도는 중간이지만 평점이 높은 책
    """
    # 1. 성향 일치 (유사도 1위)
    best_match = max(candidates, key=lambda x: x.similarity_score)
    
    # 2. 독자 만족 (평점 1위)
    best_rated = max(candidates, key=lambda x: x.avg_rating)
    
    # 3. 의외성 (유사도 4-7위 중 평점 최고)
    surprising = max(candidates[3:7], key=lambda x: x.avg_rating)
    
    return [best_match, best_rated, surprising]
```

**라벨링**
- 성향 일치: "당신의 취향과 87% 일치해요"
- 독자 만족: "95%의 독자가 만족했어요"
- 의외성: "새로운 발견이 될 거예요"

#### 6.3.2 키워드 추출 로직

목표: 도서별 특징을 나타내는 20개 핵심 키워드 추출

**추출 프로세스**
```
리뷰 텍스트 → 전처리 → TF-IDF → 감정 분석 → 키워드 선정 → DB 저장
```

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from konlpy.tag import Okt

class KeywordExtractor:
    def __init__(self):
        self.okt = Okt()
        self.stopwords = self.load_stopwords()
    
    def extract_keywords(self, reviews, top_n=20):
        """리뷰에서 상위 N개 키워드 추출"""
        # 1. 전처리
        processed_reviews = [self.preprocess(review) for review in reviews]
        
        # 2. TF-IDF 계산
        vectorizer = TfidfVectorizer(
            max_features=100,
            ngram_range=(1, 2),
            tokenizer=self.okt.nouns,
            stop_words=self.stopwords
        )
        tfidf_matrix = vectorizer.fit_transform(processed_reviews)
        feature_names = vectorizer.get_feature_names_out()
        
        # 3. 상위 키워드 선정
        tfidf_scores = tfidf_matrix.sum(axis=0).A1
        top_indices = tfidf_scores.argsort()[-top_n:][::-1]
        
        keywords = [
            {'word': feature_names[i], 'score': float(tfidf_scores[i])}
            for i in top_indices
        ]
        return keywords
```

### 7.2 저장 구조 (핵심 테이블만)

#### 7.2.2 테이블 상세 정의

**1. users (사용자)**
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL UNIQUE,
    name VARCHAR(100) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    last_login_at TIMESTAMP,
    INDEX idx_email (email),
    INDEX idx_created_at (created_at)
);
```

**2. mbti_results (독서 MBTI 결과)**
```sql
CREATE TABLE mbti_results (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    mbti_type VARCHAR(4) NOT NULL,
    test_answers JSONB NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(user_id),
    CHECK (mbti_type ~ '^[DL][EL][RF][FS]$'),
    INDEX idx_user_id (user_id),
    INDEX idx_mbti_type (mbti_type)
);
```

**3. books (도서)**
```sql
CREATE TABLE books (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    isbn VARCHAR(13) NOT NULL UNIQUE,
    title VARCHAR(255) NOT NULL,
    author VARCHAR(255) NOT NULL,
    publisher VARCHAR(100),
    publish_date DATE,
    page_count INTEGER,
    cover_image_url TEXT NOT NULL,
    category VARCHAR(50),
    genre VARCHAR(50),
    description TEXT,
    price INTEGER,
    avg_rating FLOAT DEFAULT 0,
    sentiment_score FLOAT,
    mood VARCHAR(50),
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    INDEX idx_isbn (isbn),
    INDEX idx_category_genre (category, genre),
    INDEX idx_avg_rating (avg_rating DESC)
);
```

**4. book_keywords (도서 키워드)**
```sql
CREATE TABLE book_keywords (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    keyword VARCHAR(50) NOT NULL,
    score FLOAT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(book_id, keyword),
    CHECK (score >= 0 AND score <= 1),
    INDEX idx_book_id (book_id),
    INDEX idx_keyword (keyword),
    INDEX idx_score (score DESC)
);
```

**5. user_evaluations (사용자 평가)**
```sql
CREATE TABLE user_evaluations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    rating VARCHAR(10) NOT NULL,
    read_duration_days INTEGER,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(user_id, book_id),
    CHECK (rating IN ('like', 'dislike')),
    INDEX idx_user_id (user_id),
    INDEX idx_book_id (book_id),
    INDEX idx_rating (rating),
    INDEX idx_created_at (created_at DESC)
);
```

**6. wishlists (위시리스트)**
```sql
CREATE TABLE wishlists (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    source VARCHAR(50),
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE(user_id, book_id),
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at DESC)
);
```

**7. recommendations (추천 기록)**
```sql
CREATE TABLE recommendations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    book_id UUID NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    stage VARCHAR(20) NOT NULL,
    similarity_score FLOAT,
    reason TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    CHECK (stage IN ('stage1', 'stage2', 'stage3', 'monthly', 'yearly')),
    CHECK (similarity_score >= 0 AND similarity_score <= 1),
    INDEX idx_user_id_created_at (user_id, created_at DESC),
    INDEX idx_stage (stage)
);
```

## 8. 성공 지표 (Success Metrics)

본 서비스의 성공 지표는 단순 트래픽이나 사용 빈도가 아니라,

> "개인화 추천이 실제로 유효했는가"
> "사용자가 기록과 회고를 통해 다시 돌아오는가"

를 검증하는 데 초점을 둔다.

### North Star Metric

**추천 정확도 기반 독서 완료율**

추천받은 도서 중 사용자가 실제로 읽고 👍(좋아요)를 남긴 비율

```
추천 정확도 = (👍 평가된 추천 도서 수) / (전체 추천 도서 수)
```

**선정 이유**
- 단순 클릭이나 노출이 아닌 실제 독서 경험의 질을 반영
- 추천 → 독서 → 평가 → 재추천이라는 핵심 학습 루프를 직접적으로 측정
- 서비스의 모든 핵심 기능(테스트, 추천, 평가, 리포트)이 이 지표에 기여

### 8.2 핵심 KPI (요구사항 기반 정리)

#### 8.2.1 추천 정확도

## 12. 부록

### 📝 테스트 문항 (8문항)

#### 축 1: 몰입도 (Deep vs Light)

**Q1. 주말 오후, 책을 읽고 있습니다. 당신은?**
- A) 한 권을 처음부터 끝까지 집중해서 읽는다 (D)
- B) 여러 책을 번갈아가며 읽거나, 원하는 부분만 골라 읽는다 (L)

**Q2. 읽던 책이 마음에 들 때, 당신의 다음 행동은?**
- A) 이 책을 끝까지 읽은 후 다음 책을 찾는다 (D)
- B) 비슷한 느낌의 다른 책도 함께 찾아본다 (L)

#### 축 2: 감성/이성 (Emotion vs Logic)

**Q3. 가장 기억에 남는 책은?**
- A) 마음을 울린 감동적인 이야기 (E)
- B) 새로운 관점을 제시하거나 생각할 거리를 준 책 (L)

**Q4. 책을 읽은 후 가장 하고 싶은 것은?**
- A) 느낀 감정을 곱씹거나 누군가와 공유하고 싶다 (E)
- B) 배운 내용을 정리하거나 실생활에 적용해보고 싶다 (L)

#### 축 3: 현실/상상 (Reality vs Fantasy)

**Q5. 선호하는 이야기의 배경은?**
- A) 현실적이고 공감 가능한 일상 이야기 (R)
- B) 상상력을 자극하는 판타지나 SF 세계 (F)

**Q6. 책을 읽을 때 더 몰입하게 되는 것은?**
- A) "이런 일이 실제로 있을 수 있겠다"는 현실감 (R)
- B) "이런 세계도 가능하구나"라는 상상의 확장 (F)

#### 축 4: 빠른/느린 (Fast vs Slow)

**Q7. 선호하는 책의 전개 방식은?**
- A) 빠르게 전개되며 몰입감 있는 스토리 (F)
- B) 천천히 흘러가며 여운을 남기는 서사 (S)

**Q8. 출퇴근길이나 짧은 시간에 읽기 좋은 책은?**
- A) 술술 읽히고 빠르게 진행되는 책 (F)
- B) 한 문장 한 문장 음미하며 읽을 수 있는 책 (S)

### 🎯 점수 계산 방식

각 축마다 2문항씩 → A 선택 시 첫 번째 유형에 +1점, B 선택 시 두 번째 유형에 +1점

**최종 결과 예시:**
- 축 1: D 2점, L 0점 → D
- 축 2: E 1점, L 1점 → 동점일 경우 E (감성 우선)
- 축 3: R 2점, F 0점 → R
- 축 4: F 1점, S 1점 → 동점일 경우 F (빠른 전개 우선)
- **결과: DERF형**
